## Theory

**I²C** is a **two-wire**, **multi-master-capable**, **half-duplex** bus:

| Signal | Role |
|--------|------|
| **SDA** | Serial Data |
| **SCL** | Serial Clock |

Both lines are **open-drain** with **pull-up resistors** (4.7 kΩ typical on 3.3 V; 2.2 kΩ for short buses).

### Addressing

Each slave has a **7-bit address**. Master sends:

```
START | ADDR[6:0] + R/W | ACK | DATA... | STOP
```

- **R/W = 0:** write to slave
- **R/W = 1:** read from slave

### ACK / NACK

Receiver pulls SDA **low** on the 9th clock for ACK. NACK (SDA high) means wrong address, device off, or missing pull-ups.

### Clock stretching

Slow slaves hold SCL low; master must wait. ESP32 hardware handles stretching; bit-bang implementations often miss it.

### Speed modes

| Mode | Max clock |
|------|-----------|
| Standard | 100 kHz |
| Fast | 400 kHz |
| Fast Mode Plus | 1 MHz |

## Hardware Overview

### ESP32-S3 I²C

Two controllers (**I2C0**, **I2C1**), pins via **GPIO matrix**. Master mode typical; hardware glitch filter; timeout recovery on some HAL versions.

### Common peripherals

| Part | Address | Function |
|------|---------|----------|
| BME280 | 0x76 / 0x77 | Temp/humidity/pressure |
| SSD1306 | 0x3C | OLED |
| MPU6050 | 0x68 | IMU |
| PCF8574 | 0x20–0x27 | GPIO expander |

## ASCII Wiring

```
ESP32-S3              BME280 Module
┌──────────┐          ┌──────────┐
│ GPIO8    ├── SDA ──┤ SDA      │
│ GPIO9    ├── SCL ──┤ SCL      │
│ 3V3      ├─────────►│ VIN      │
│ GND      ├─────────►│ GND      │
└──────────┘          └──────────┘
     │    │
     └────┴── 4.7 kΩ pull-ups to 3V3 (often on breakout)
```

Keep bus capacitance low; long cables need stronger pull-ups or lower speed.

## Memory & Register Notes

### ESP32-S3 I²C registers (conceptual)

| Register | Purpose |
|----------|---------|
| `I2C_SCL_LOW` | Clock low period |
| `I2C_SCL_HIGH` | Clock high period |
| `I2C_DATA` | TX/RX FIFO |
| `I2C_CMD` | START, STOP, READ, WRITE commands |
| `I2C_INT_RAW` | NACK, timeout, complete |

### Transaction buffer

```swift
struct I2CWriteTransaction {
    var address: UInt8   // 7-bit, shifted left by driver
    var register: UInt8
    var payload: [UInt8]
}
```

Keep payloads on stack or in static storage — avoid heap in ISRs.

## HAL Swift Example — BME280 Read (ESP-IDF)

```swift
import ESPIDF

struct BME280 {
    let i2c: I2CBus
    let address: UInt8 = 0x76

    func readID() -> UInt8 {
        return i2c.readRegister(address: address, reg: 0xD0)
    }

    func readTemperatureC() -> Float {
        let raw = i2c.readRegisters(address: address, reg: 0xFA, count: 3)
        let adc = (Int32(raw[0]) << 12) | (Int32(raw[1]) << 4) | (Int32(raw[2]) >> 4)
        return compensateTemperature(adc: adc)
    }

    private func compensateTemperature(adc: Int32) -> Float {
        // Load calibration from 0x88..0xA1 — datasheet formulas
        _ = adc
        return 0.0 // placeholder
    }
}

@main
struct I2CScannerApp {
    static func main() {
        let i2c = I2CBus(port: 0, sda: 8, scl: 9, frequencyHz: 400_000)

        // Scan bus 0x03..0x77
        for addr in 0x03...0x77 {
            if i2c.probe(address: UInt8(addr)) {
                print("Found device at 0x\(String(addr, radix: 16))")
            }
        }

        let sensor = BME280(i2c: i2c)
        print("BME280 chip ID: 0x\(String(sensor.readID(), radix: 16))")
    }
}
```

## Bare-Metal Swift Sketch

```swift
import MMIO

let i2c0 = I2C0(baseAddress: 0x6001_3000)

func i2cWrite(address: UInt8, data: [UInt8]) -> Bool {
    i2c0.enable.set(true)
    // Queue START + addr(W) + bytes + STOP via I2C_CMD registers
    i2c0.cmd.start.set(true)
    i2c0.data.set(UInt32((UInt16(address) << 1) | 0)) // write
    // ... push data bytes, check ACK bits in status
    i2c0.cmd.stop.set(true)
    return !i2c0.int_raw.nack.get()
}
```

## Host Swift — I²C via macOS (development / test)

Use I²C USB adapters or delegate to a Raspberry Pi companion during driver development:

```swift
import Foundation

/// Protocol mirroring embedded I2CBus — test on host, deploy on MCU
protocol I2CBusProtocol {
    func write(address: UInt8, register: UInt8, data: [UInt8]) throws
    func read(address: UInt8, register: UInt8, count: Int) throws -> [UInt8]
}

struct BME280Driver<Bus: I2CBusProtocol> {
    let bus: Bus
    let address: UInt8

    func chipID() throws -> UInt8 {
        try bus.read(address: address, register: 0xD0, count: 1)[0]
    }
}
```

## Common Mistakes

| Mistake | Symptom | Fix |
|---------|---------|-----|
| Missing pull-ups | Bus stuck high, no ACK | Add 4.7 kΩ to SDA and SCL |
| Wrong 7-bit vs 8-bit address | NACK always | Shift: `(addr << 1) \| rw` |
| SDA/SCL swapped | No devices found | Swap wires |
| Address conflict | Intermittent NACK | Multiplexer or second bus |
| 5 V sensor on 3.3 V I²C | Damaged ESP32 | Level shifter or 3.3 V part |
| Clock too fast on long cable | CRC-like errors | Drop to 100 kHz |

## Debugging Tips

- Run **I²C scanner** first — confirms wiring and pull-ups.
- Logic analyzer decode on SDA/SCL — verify START/STOP/ACK.
- Check breakout **ADDR pin** (BME280: 0x76 vs 0x77).
- Scope SCL — stretched low means slave is slow but alive.

---

## Performance Tips

- Batch register reads (BME280 burst from 0xF7) vs per-field reads.
- Use 400 kHz when wiring is short and stable.
- Cache calibration coefficients at boot — don't re-read every sample.
- For displays (SSD1306), buffer entire frame in RAM, send in one transaction.
