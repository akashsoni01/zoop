# ILI9341 — 240×320 Color TFT

The **ILI9341** drives **240×320 RGB565** TFT panels over SPI — common on 2.4″ and 2.8″ displays.

**Prerequisites:** [16-spi.md](../16-spi.md), [08-gpio.md](../08-gpio.md)

---

## Working Principle

TFT LCD with **ILI9341 controller** containing GRAM (240×320×16-bit). MCU sends commands to set window address, then streams RGB565 pixel data. Backlight LED separate from controller.

---

## Datasheet Notes

| Parameter | Value |
|-----------|-------|
| Resolution | 240×320 |
| Color depth | 262K (RGB565 interface) |
| SPI clock | Up to 10 MHz (write) |
| Voltage | 3.3 V logic and IO |

---

## Protocol

**4-wire SPI**: CS, DC, RST + MOSI/SCK. DC=0 command, DC=1 pixel data.

Memory write command `0x2C` after column (`0x2A`) and row (`0x2B`) set.

See [16-spi.md](../16-spi.md).

---

## Register Map

| Cmd | Code | Description |
|-----|------|-------------|
| SWRESET | `0x01` | Software reset |
| SLPOUT | `0x11` | Sleep out |
| MADCTL | `0x36` | Memory access control / rotation |
| COLMOD | `0x3A` | Pixel format (`0x55` = 16-bit) |
| CASET | `0x2A` | Column address |
| PASET | `0x2B` | Page address |
| RAMWR | `0x2C` | Write GRAM |
| DISPON | `0x29` | Display on |

## ESP32-S3 Wiring

```
ILI9341             ESP32-S3
───────             ────────
VCC  ─────────────► 3V3
GND  ─────────────► GND
CS   ◄───────────── GPIO10
RST  ◄───────────── GPIO15
DC   ◄───────────── GPIO14
SDI  ◄───────────── GPIO11 (MOSI)
SCK  ◄───────────── GPIO12
LED  ◄───────────── GPIO16 (backlight)
```

MISO often not connected on display modules.

## Swift Driver Sketch

```swift
struct ILI9341<S: SPIBus> {
    var spi: S
    var dc: any DigitalPin
    var cs: any DigitalPin
    var rst: any DigitalPin

    mutating func initDisplay() throws {
        try hardwareReset()
        try writeCommand(0x01); delayMs(150)
        try writeCommand(0x11); delayMs(120) // sleep out
        try writeCommand(0x3A, data: [0x55])  // RGB565
        try writeCommand(0x36, data: [0x48])  // rotation
        try writeCommand(0x29)                  // display on
    }

    mutating func fillRect(x: Int, y: Int, w: Int, h: Int, color: UInt16) throws {
        try setWindow(x: x, y: y, w: w, h: h)
        try writeCommand(0x2C)
        var pixels = [UInt8](repeating: 0, count: w * h * 2)
        for i in stride(from: 0, to: pixels.count, by: 2) {
            pixels[i] = UInt8(color >> 8)
            pixels[i+1] = UInt8(color & 0xFF)
        }
        try writeData(pixels)
    }

    private mutating func setWindow(x: Int, y: Int, w: Int, h: Int) throws {
        try writeCommand(0x2A, data: [UInt8(x >> 8), UInt8(x & 0xFF),
                                      UInt8((x+w-1) >> 8), UInt8((x+w-1) & 0xFF)])
        try writeCommand(0x2B, data: [UInt8(y >> 8), UInt8(y & 0xFF),
                                      UInt8((y+h-1) >> 8), UInt8((y+h-1) & 0xFF)])
    }
}
```

Use line buffer (240×2×2 bytes) for RAM-constrained builds.

---

## Bare-Metal Notes

- SPI DMA essential for smooth UI at 240×320.
- MADCTL value sets rotation — swap width/height in software accordingly.
- Backlight on separate FET — PWM dimming via GPIO16.

---

## HAL / Protocol-Oriented Driver Notes

`ColorDisplay` protocol: `fillRect`, `drawBitmap`, `setRotation`. RGB565 color type as `UInt16`.

---

## Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| White screen | No init / RST | Check reset timing |
| Wrong colors | Endian swap | Swap high/low byte |
| SPI garbage | Mode mismatch | SPI mode 0 |
| Banding | Window not set | Send CASET/PASET before RAMWR |
