# RS-485 — Differential Serial Bus

**RS-485** is a **differential**, **half-duplex** serial bus supporting **32+ nodes** on twisted pair up to **1200 m**. Common in industrial PLCs, building automation, and Modbus RTU.

**Prerequisites:** [uart-usart.md](./uart-usart.md)

---

## Theory

**Differential signaling:** Logic defined by **A − B** voltage, not absolute ground — excellent noise rejection.

| Mode | Wires | Direction |
|------|-------|-----------|
| Half-duplex | A, B, GND | One driver at a time |
| Full-duplex (422) | A/B TX + A/B RX | Simultaneous (less common) |

Transceiver **DE** (driver enable) and **RE** (receiver enable, active-low) tie together on many modules — MCU GPIO controls transmit mode.

---

## Timing Diagram (ASCII)

Half-duplex turnaround (master TX then RX):

```
DE (driver enable)  ────┐              ┌────
                        └──────────────┘

UART TX             ────[ request ]──────

UART RX             ────────────────[ response ]──

Bus A-B             ──── differential bursts ────
```

Turnaround delay required between end of TX and start of listening (device dependent, 1–5 ms typical).

---

## Packet Format

RS-485 carries **application protocols** — most often [modbus.md](./modbus.md) RTU:

| Field | Modbus RTU example |
|-------|-------------------|
| Address | 1 byte (1–247) |
| Function | 1 byte |
| Data | N bytes |
| CRC-16 | 2 bytes (LSB first) |

Raw ASCII protocols also exist on RS-485 links.

---

## Electrical Characteristics

| Parameter | Guideline |
|-----------|-----------|
| Nodes | Up to 32 unit loads (more with repeaters) |
| Termination | 120 Ω at **both ends** of bus |
| Bias | Fail-safe pull to defined idle (optional) |
| Cable | Twisted pair, 120 Ω characteristic |
| Max distance | 1200 m @ 9600 baud |
| Transceivers | MAX485, SN65HVD1782 |

Connect **GND reference** between nodes — differential still needs return path.

## Swift HAL Sketch

```swift
import Embedded
import ESP32Hardware

struct RS485Port {
    var uart: UART2
    var de: GPIO.Output<GPIO4>  // driver enable

    mutating func transmit(_ data: [UInt8]) {
        de.setHigh()  // enable driver
        uart.write(data)
        uart.flush()
        de.setLow()   // enable receiver
    }

    mutating func receive(into buffer: inout [UInt8], timeoutMs: UInt32) -> Int {
        uart.read(into: &buffer, timeoutMs: timeoutMs)
    }
}
```

**Ownership:** Exclusive bus access — mutex if multiple tasks share RS-485.

## Common Mistakes

1. **DE left high** — can't receive responses.
2. **No termination** — reflections at high baud.
3. **Star wiring** — use linear bus topology.
4. **Ground potential difference** — use isolated transceiver.
5. **Turnaround too short** — truncated response frames.
