# BME280 — Pressure, Temperature & Humidity

The **Bosch BME280** combines barometric pressure, temperature, and **relative humidity** in one package. It shares the BMP280's pressure/temp front-end and adds a capacitive humidity sensor.

**Prerequisites:** [bmp280.md](./bmp280.md), [17-i2c.md](../17-i2c.md)

---

## Working Principle

Three independent MEMS/steady-state elements on one die:

1. **Pressure** — piezo-resistive (same as BMP280)
2. **Temperature** — for compensation of all channels
3. **Humidity** — capacitive polymer, measured on a separate conversion path

All outputs are **factory trimmed**; compensation uses coefficients in registers `0x88`–`0xA1` (temp/press) and `0xE1`–`0xF0` (humidity).

---

## Datasheet Key Points

| Parameter | Value |
|-----------|-------|
| `chip_id` (0xD0) | `0x60` |
| I²C address | `0x76` / `0x77` (SDO) |
| Humidity range | 0–100 %RH |
| Interface | I²C, SPI |

**Do not confuse with BMP280** (`chip_id = 0x58`) — always verify ID before init.

---

## Protocol

Identical bus mechanics to BMP280. See [bmp280.md](./bmp280.md) for I²C/SPI wiring on ESP32-S3 (GPIO8/9 for I²C).

Humidity requires enabling **humidity oversampling** in `ctrl_hum` (`0xF2`) **before** writing `ctrl_meas`.

---

## Register Map (Essential)

| Addr | Name | Description |
|------|------|-------------|
| `0xD0` | `chip_id` | `0x60` |
| `0xE1`–`0xF0` | Humidity trim | `dig_H1`–`dig_H6` |
| `0x88`–`0x9F` | Temp/press trim | Shared with BMP280 layout |
| `0xF2` | `ctrl_hum` | Humidity oversampling only |
| `0xF4` | `ctrl_meas` | Temp, press OS + mode |
| `0xF5` | `config` | Filter, standby |
| `0xF7`–`0xFE` | Data | Press(3), Temp(3), Hum(2), padding |

Data burst read from `0xF7` returns **8 bytes** (press + temp + hum).

### Init Sequence (Critical Order)

```text
1. Read chip_id → 0x60
2. Read all calibration registers
3. Write ctrl_hum (0xF2) — e.g. 0x01 (OS x1)
4. Write ctrl_meas (0xF4) — temp, press, mode
5. Write config (0xF5) — optional filter
6. Wait for first conversion
```

Skipping step 3 before step 4 leaves humidity disabled.

---

## Compensation

BME280 uses three algorithms (datasheet §4.2):

- **Temperature** — sets internal `t_fine` (required first)
- **Pressure** — uses `t_fine`
- **Humidity** — uses `t_fine` and hum calibration bytes

```rust
fn compensate_humidity(t_fine: i32, adc_h: u32, cal: &Bme280Cal) -> f32 {
    let var1 = t_fine as f32 - 76800.0;
    let var2 = adc_h as f32 - (cal.h4 as f32 * 64.0 + cal.h5 as f32 / 16384.0 * var1);
    let var3 = cal.h6 as f32 / 65536.0;
    // ... complete per datasheet
    var2 * var3 * (1.0 + cal.h3 as f32 / 67108864.0 * var2 * (1.0 + cal.h2 as f32 / 67108864.0 * var2))
}
```

Use integer math from the datasheet for `no_std` without FPU if needed.

## ESP32-S3 Wiring

Same as BMP280:

```
GPIO8 → SDA, GPIO9 → SCL, 3V3, GND
```

Many GY-BME280 modules include a 3.3 V regulator — safe on ESP32-S3 3V3 rail.

## Rust Driver Sketch

```rust
use embedded_hal::delay::DelayNs;
use embedded_hal::i2c::I2c;

pub struct Bme280<I2C, DELAY> {
    i2c: I2C,
    delay: DELAY,
    addr: u8,
    cal: Bme280Cal,
    t_fine: i32,
}

impl<I2C, DELAY, E> Bme280<I2C, DELAY>
where
    I2C: I2c<Error = E>,
    DELAY: DelayNs,
{
    pub fn init(&mut self) -> Result<(), E> {
        let id = self.read_u8(0xD0)?;
        if id != 0x60 { return Err(/* ... */); }
        self.cal = self.load_calibration()?;
        self.write_u8(0xF2, 0x01)?;           // hum OS x1
        self.write_u8(0xF4, 0b001_001_11)?;   // temp OS x1, press OS x1, normal
        self.write_u8(0xF5, 0b000_100_00)?;   // filter coeff 4
        self.delay.delay_ms(100);
        Ok(())
    }

    pub fn read_env(&mut self) -> Result<(f32, f32, f32), E> {
        let mut d = [0u8; 8];
        self.i2c.write_read(self.addr, &[0xF7], &mut d)?;
        // parse adc_p, adc_t, adc_h → compensate
        todo!("compensation")
    }
}
```

## Bare-Metal Notes

- **Forced mode** useful for low power: trigger one shot, sleep MCU, read, repeat.
- **Normal mode** with `t_sb=1000 ms` gives ~1 Hz updates at ~0.1 mA.
- Humidity sensor has **slow response** (~1 s) — do not expect instant step changes.
- Keep sensor **ventilated** but shielded from direct airflow for stable RH.

## Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| RH always ~0 | `ctrl_hum` not set | Write 0xF2 before 0xF4 |
| Wrong chip ID | BMP280 module mislabeled | Check 0xD0 |
| Humidity saturated | Condensation | Enable BME280 heater (not in BME280 — use SHT31 for heater); warm-up period |
| I²C errors with Wi-Fi | Bus noise | Shorter wires, 2.2 kΩ pull-ups |
