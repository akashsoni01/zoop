# RS-232 — Legacy Serial Interface

**RS-232** is an **asynchronous serial** standard using **single-ended ± voltage levels** (not TTL). It once connected PCs to modems; embedded use today: industrial equipment, CNC, legacy PLCs.

**Prerequisites:** [uart-usart.md](./uart-usart.md)

---

## Theory

RS-232 defines **DTE** (Data Terminal Equipment, e.g., PC) vs **DCE** (Data Circuit-terminating Equipment, e.g., modem). Signals include **TX**, **RX**, **RTS**, **CTS**, **DTR**, **DSR** (hardware flow control).

Logic levels:

| State | RS-232 | TTL (ESP32) |
|-------|--------|-------------|
| Mark (idle) | −3 V to −15 V | 3.3 V HIGH |
| Space (active) | +3 V to +15 V | 0 V LOW |

**Inverted** relative to TTL UART. **Never** connect RS-232 directly to ESP32 pins.

## Timing Diagram (ASCII)

9600 baud, 8N1 (same framing as UART, different voltage):

```
RS-232 TX line (simplified voltage):

+12V ─────┐     ┌─────┐           mark (idle)
          │     │     │
  0V      │     │     │
          └─────┘     └──── ...
        space(start)  mark(stop)

TTL side after MAX3232:

3.3V ────────┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ───
           └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘
           (inverted polarity vs RS-232)
```

## Packet Format

Same byte framing as [uart-usart.md](./uart-usart.md) — application defines content (Modbus RTU, ASCII protocols, proprietary).

DB9 pinout (common DTE):

| Pin | Signal |
|-----|--------|
| 2 | RX (into DTE) |
| 3 | TX (out of DTE) |
| 5 | GND |

Cross **TX↔RX**; connect **GND**.

## Rust HAL Sketch

```rust
use esp_hal::uart::{Uart, Config};
use embedded_io::{Read, Write};

// MCU UART is TTL — MAX3232 on board handles RS-232 levels
pub fn read_line(uart: &mut Uart<'static, esp_hal::Blocking>, buf: &mut [u8]) -> usize {
    let mut i = 0;
    while i < buf.len() {
        let mut b = [0u8];
        if uart.read(&mut b).ok() == Some(1) {
            if b[0] == b'\n' { break; }
            buf[i] = b[0];
            i += 1;
        }
    }
    i
}
```

**Ownership:** Same as UART — one `Uart` peripheral, transceiver is passive.

## Common Mistakes

1. **Direct TTL ↔ RS-232** — destroys GPIO.
2. **Null modem confusion** — DTE-DTE needs cross or null modem cable.
3. **Flow control not wired** — buffer overruns at high baud.
4. **Ground not connected** — framing errors.
5. **Wrong gender/pinout** on DB9.
