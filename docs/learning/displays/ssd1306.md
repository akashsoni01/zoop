# SSD1306 — 128×64 OLED Display

Monochrome **OLED** controller supporting **I²C** and **SPI** — the most common small display in hobby Embedded Rust projects.

**Prerequisites:** [17-i2c.md](../17-i2c.md), [16-spi.md](../16-spi.md), [07-hal.md](../07-hal.md)

---

## Theory

**OLED (Organic Light-Emitting Diode)** pixels emit light directly — no backlight. The **SSD1306** controller drives a 128×64 dot matrix:

- **GDDRAM** (Graphic Display Data RAM): 1 bit per pixel, 128×64 / 8 = **1024 bytes**
- **Page addressing:** memory organized as 8 vertical pages × 128 columns
- Contrast controlled by charge pump voltage (command `0x81`)

Refresh rate high enough for static UI; burn-in possible if pixels stay on for weeks — use screensaver for static text.

## Wiring (ESP32-S3, I²C)

```
SSD1306 Module      ESP32-S3
──────────────      ────────
VCC  ─────────────► 3V3
GND  ─────────────► GND
SDA  ─────────────► GPIO8
SCL  ─────────────► GPIO9
```

### SPI Variant (if module has SPI pins)

```
SSD1306             ESP32-S3
───────             ────────
D0 (CLK)  ◄──────── GPIO12 (SCK)
D1 (MOSI) ◄──────── GPIO11
DC        ◄──────── GPIO14
RST       ◄──────── GPIO15
CS        ◄──────── GPIO10
3V3 / GND           3V3 / GND
```

See [08-gpio.md](../08-gpio.md) for reset pin sequencing.

## Protocol

### I²C

| Parameter | Value |
|-----------|-------|
| Address | `0x3C` (common) or `0x3D` |
| Control byte | `0x00` = command, `0x40` = data stream |

Write pattern: `[control] [cmd...]` or `[0x40] [gdram bytes...]`

### SPI

DC low → command, DC high → data. CS strobed per byte/burst.

### Init Command Sequence (Essential)

```text
DISPLAY OFF → CLOCK/DIV → MULTIPLEX(63) → OFFSET → START_LINE
CHARGE PUMP → MEMORY MODE (horizontal) → SEG_REMAP | COM_SCAN
COM PINS → CONTRAST → PRECHARGE → VCOM → DISPLAY ON
```

Use proven sequence from `ssd1306` crate — order matters.

## Framebuffer Concepts

| Approach | RAM | Use Case |
|----------|-----|----------|
| Full buffer | 1024 B | embedded-graphics DrawTarget |
| Partial buffer | 128 B (1 page) | Stream columns |
| Direct draw | 0 | Write primitives without buffer (harder) |

**Horizontal addressing mode** lets you burst-write contiguous GDDRAM — fastest flush.

```rust
// 1 bit per pixel: byte packs 8 vertical pixels in one column page
// buffer[y/8][x] bit (y%8) → pixel (x,y)
```

## Rust + embedded-graphics

`Cargo.toml`:

```toml
[dependencies]
ssd1306 = "0.8"
embedded-graphics = "0.8"
display-interface-i2c = "0.7"
display-interface = "0.5"
```

Example (esp-hal I²C):

```rust
use embedded_graphics::{
    mono_font::{ascii::FONT_6X10, MonoTextStyle},
    pixelcolor::BinaryColor,
    prelude::*,
    text::Text,
};
use ssd1306::{prelude::*, I2CDisplayInterface, Ssd1306};

let interface = I2CDisplayInterface::new(i2c);
let mut display = Ssd1306::new(interface, DisplaySize128x64, DisplayRotation::Rotate0)
    .into_buffered_graphics_mode();
display.init().unwrap();

Text::new("Hello Rust!", Point::new(0, 10), MonoTextStyle::new(&FONT_6X10, BinaryColor::On))
    .draw(&mut display)
    .unwrap();
display.flush().unwrap();
```

**Traits:** `DrawTarget` for drawing; `flush()` pushes buffer to panel.

## Common Mistakes

| Mistake | Symptom | Fix |
|---------|---------|-----|
| Wrong I²C address | No display | Scan bus; try 0x3D |
| Skip charge pump cmd | Blank screen | Include `0x8D, 0x14` sequence |
| No flush | Blank after draw | Call `flush()` after drawing |
| Confuse page vs pixel Y | Vertical stripes | Use buffered driver or correct Y math |
| 5 V on VCC | Damaged module | 3.3 V only on most breakouts |
| Long I²C wires | Corrupted pixels | 2.2 kΩ pull-ups; shorten cables |
