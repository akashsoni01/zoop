# ILI9341 — 240×320 Color TFT

The **Ilitek ILI9341** drives **240×320 RGB TFT** panels over **4-wire SPI** — common on 2.4" and 2.8" breakout boards.

**Prerequisites:** [16-spi.md](../16-spi.md), [08-gpio.md](../08-gpio.md)

---

## Theory

**TFT LCD** uses thin-film transistor per subpixel. ILI9341 **GRAM** stores 240×320 × 18-bit color (driver accepts 16-bit RGB565 on SPI for efficiency).

- **RGB565:** 5 red, 6 green, 5 blue — 2 bytes/pixel
- Full framebuffer: 240×320×2 = **153,600 bytes** — too large for MCU SRAM; use **line buffering** or **partial windows**

Scan direction set via **MADCTL** (`0x36`) — controls rotation and RGB/BGR order.

## Wiring (ESP32-S3, SPI)

```
ILI9341 Module      ESP32-S3
──────────────      ────────
VCC  ─────────────► 3V3 (or 5V if module has reg — check!)
GND  ─────────────► GND
CS   ◄───────────── GPIO10
RESET◄───────────── GPIO15
DC/RS◄───────────── GPIO14
MOSI ◄───────────── GPIO11
SCK  ◄───────────── GPIO12
MISO ─────────────► NC (often unconnected)
LED  ◄───────────── GPIO16 (backlight, PWM optional)
```

```
        ┌─────────────┐
        │  ILI9341    │
VCC ────┤ VCC     LED ├──── GPIO16 (via transistor if high current)
GND ────┤ GND     SCK ├──── GPIO12
      ┌─┤ CS      MOSI├──── GPIO11
ESP   │ │ DC      MISO│    (NC)
      │ │ RST         │
      └─┴─────────────┘
```

See [11-pwm.md](../11-pwm.md) for backlight dimming.

## Protocol

### SPI

| Mode | CPOL=0, CPHA=0 (Mode 0) typical |
| Speed | 20–40 MHz ESP32-S3 (verify wiring) |

**DC/RS:** LOW = command byte, HIGH = parameter/pixel data.

### Key Commands

| Cmd | Name | Purpose |
|-----|------|---------|
| `0x01` | SWRESET | Software reset |
| `0x11` | SLPOUT | Exit sleep |
| `0x3A` | COLMOD | Pixel format (`0x55` = 16-bit) |
| `0x36` | MADCTL | Memory access control / rotation |
| `0x2A` | CASET | Column address |
| `0x2B` | RASET | Row address |
| `0x2C` | RAMWR | Write pixels |
| `0x29` | DISPON | Display on |

### Window + Pixel Write

```text
CASET: x_start, x_end (16-bit each)
RASET: y_start, y_end
RAMWR: (x_end-x_start+1)*(y_end-y_start+1) × 2 bytes RGB565
```

## Framebuffer Concepts

| Strategy | RAM | Notes |
|----------|-----|-------|
| Full frame | 150 KB | Needs PSRAM on ESP32 |
| Line buffer (1 row) | 480 B | Draw scanline-by-scanline |
| Tile buffer (e.g. 240×40) | 19.2 KB | Good compromise |
| Direct primitive | Minimal | Draw rects/lines to window |

**embedded-graphics** `DrawTarget` on a `Framebuffer<C, RawU16Rgb565>` tile — flush tile to GRAM window.

## Rust + embedded-graphics

```toml
[dependencies]
ili9341 = "0.6"
embedded-graphics = "0.8"
embedded-graphics-framebuffer = "0.5"
display-interface-spi = "0.5"
mipidsi = "0.8"  # alternative unified driver
```

Using `mipidsi` (supports ILI9341):

```rust
use embedded_graphics::{prelude::*, primitives::{Rectangle, PrimitiveStyle}};
use mipidsi::Builder;
use display_interface_spi::SPIInterface;

let interface = SPIInterface::new(spi, dc, cs);
let mut display = Builder::new(ili9341::model::ILI9341, interface)
    .reset_pin(rst)
    .init(&mut delay)
    .unwrap();

Rectangle::new(Point::new(20, 30), Size::new(100, 50))
    .into_styled(PrimitiveStyle::with_fill(Rgb565::BLUE))
    .draw(&mut display)
    .unwrap();
```

For performance, enable **DMA SPI** on ESP32-S3 ([16-spi.md](../16-spi.md)).

## Common Mistakes

| Mistake | Symptom | Fix |
|---------|---------|-----|
| MADCTL wrong | Wrong colors/rotation | Set BGR bit if red/blue swapped |
| No reset pulse | White screen | Toggle RST low 10 ms |
| SPI too fast | Glitchy image | Reduce to 20 MHz; short wires |
| COLMOD not 0x55 | Wrong pixel width | Set 16-bit color |
| Backlight off | Dark panel | Drive LED pin |
| Full buffer OOM | Link/runtime fail | Use line/tile buffer |
