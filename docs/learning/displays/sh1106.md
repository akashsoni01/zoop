# SH1106 — 128×64 OLED Display

The **SH1106** controller drives 132×64 OLED panels but displays **128×64** — the extra columns cause a common **horizontal offset** bug if treated like SSD1306.

**Prerequisites:** [ssd1306.md](./ssd1306.md), [17-i2c.md](../17-i2c.md)

---

## Theory

Like SSD1306, SH1106 uses **page-oriented GDDRAM** (1 bit per pixel). Internal RAM is **132 columns × 64 rows**; visible window is typically columns 2–129 ( **+2 column offset** ).

Some modules label "SSD1306" but contain SH1106 — if text is shifted right, you have SH1106.

---

## Wiring (ESP32-S3, I²C)

Identical to SSD1306:

```
SH1106 Module       ESP32-S3
─────────────       ────────
VCC  ─────────────► 3V3
GND  ─────────────► GND
SDA  ─────────────► GPIO8
SCL  ─────────────► GPIO9
```

SPI wiring same as [ssd1306.md](./ssd1306.md) SPI table if applicable.

---

## Protocol

### I²C

| Address | `0x3C` or `0x3D` |
| Control byte | `0x00` commands, `0x40` data |

### Column Offset (Critical Difference)

When setting column address, SH1106 needs **+2 offset**:

```text
Lower column: 0x00 + 2 = 0x02
Upper column: 0x10 + 0 = 0x10  (for column 0 start)
```

Drivers handle this in `set_position()` — if rolling your own, apply offset on every line write.

### Init Sequence

Similar to SSD1306 but:

- Different **COM pin config** values
- **Charge pump** commands differ slightly
- Enable **DC-DC** internal boost: command sequence per Sitronix datasheet

---

## Framebuffer Concepts

Same 1024-byte logical buffer as 128×64 SSD1306. Physical writes must map:

```text
logical x (0..127) → hardware column (x + 2)
```

Buffered drivers (`sh1106` crate) hide offset in `flush()`.

## Rust + embedded-graphics

```toml
[dependencies]
sh1106 = "0.5"
embedded-graphics = "0.8"
display-interface-i2c = "0.7"
```

```rust
use sh1106::{prelude::*, I2CDisplayInterface, Sh1106};

let interface = I2CDisplayInterface::new(i2c);
let mut display = Sh1106::new(interface, DisplaySize128x64, DisplayRotation::Rotate0)
    .into_buffered_graphics_mode();
display.init().unwrap();

// embedded-graphics drawing identical to SSD1306
display.flush().unwrap();
```

**Do not** use `ssd1306` crate on SH1106 hardware without offset patch — text will clip/shift.

## Common Mistakes

| Mistake | Symptom | Fix |
|---------|---------|-----|
| SSD1306 driver on SH1106 | Text shifted 2 px | Use `sh1106` crate |
| Ignore column offset in custom driver | Left column blank | Add +2 to column addr |
| Wrong COM pins cmd | Dim or missing rows | SH1106-specific init table |
| Mix SPI/I²C init | Garbage | Match module jumper |

## Exercises

1. **Identify your chip** — Run I²C scan; if SSD1306 init fails visually, try SH1106 driver.
2. **Side-by-side** — Document pixel (0,0) LED position vs SSD1306 module.
3. **Animation** — Bouncing box; verify no column ghosting at left edge.
4. **Offset experiment** — Temporarily remove +2 offset in driver; screenshot/debug shift.
