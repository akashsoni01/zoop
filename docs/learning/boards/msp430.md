# MSP430 Board Guide

**16-bit ultra-low-power** MCUs from Texas Instruments — FRAM variants combine low power with practically unlimited write endurance.

Example: **MSP430FR2xx LaunchPad**.

---

## Overview

| Spec | MSP430FR2433 LaunchPad (example) |
|------|----------------------------------|
| **PCB size** | **~70 × 51 mm** (TI LaunchPad / BoosterPack outline) |
| **CPU** | 16-bit MSP430 @ 16 MHz |
| **Flash/FRAM** | 15.5 KB FRAM |
| **SRAM** | 4 KB |
| **Debug** | eZ-FET on LaunchPad (SBW) |
| **Radio** | None (use MSP430 + ESP for IoT) |
| **Headers** | 2.54 mm BoosterPack |

### Board dimensions

TI **LaunchPad** boards are roughly credit-card half-size (~2.0″ × 2.75″). Exact mm vary by FR2xxx vs FR5xxx kits — check the LaunchPad user’s guide DXF before designing a BoosterPack-compatible enclosure.

---

## Memory Map Overview

MSP430 uses unified linear address space (von Neumann):

```
0x0000 – 0x000F ─── Special function registers
0x0010 – 0x00FF ─── Peripheral registers
0x0200 – 0x2FFF ─── RAM (device dependent)
0x8000 – 0xFFFF ─── FRAM / flash code region (FRAM devices)
```

**FRAM** — ferroelectric RAM: written like SRAM, persists across power loss, **no wear leveling** concerns like flash.

Code executes directly from FRAM — fast wake from sleep — [24-low-power.md](../24-low-power.md).

## GPIO Layout Notes

LaunchPad MSP430FR2433:

| Pin | Function |
|-----|------------|
| **P1.0** | Red LED |
| **P1.3** | Button (S2) |
| **P1.4/P1.5** | I²C / SPI options |
| **P1.2/P1.3** | UART |

Port pins: **PxDIR** (direction), **PxOUT**, **PxIN**, **PxSEL** (peripheral function).

**3.3 V** on LaunchPad — verify when stacking BoosterPacks.

---

## Clock Tree

```
DCO (internal) ──► 1–16 MHz adjustable
    │
    ├── MCLK — CPU
    ├── SMCLK — fast peripherals (UART, SPI)
    └── ACLK — low-speed (32768 Hz crystal optional for RTC)
```

**CS** (Clock System) module configures sources. Low-power modes gate clocks aggressively — wake latency vs [24-low-power.md](../24-low-power.md) budget.

---

## Boot Sequence

1. Power-on reset — vector at FRAM reset handler.
2. **BSL** (Bootstrap Loader) via UART if invoked — factory programming.
3. LaunchPad **eZ-FET** programs via **Spy-Bi-Wire (SBW)** — 2-wire debug.

Rust flash (tooling evolving):

```bash
# msp430-flasher or probe-rs if supported for your variant
cargo msp430flash --chip msp430fr2433
```

Check [msp430-rs](https://github.com/rust-embedded/msp430) for current flash workflow.

## Flash & RAM

| | FR2433 |
|---|--------|
| FRAM | 15.5 KB (code + const) |
| RAM | 4 KB |

More headroom than AVR but far less than ESP32 — ideal for **energy harvesting** sensor nodes.

## Interrupt Vectors Overview

Fixed vector table at top of FRAM:

| Vector | Source |
|--------|--------|
| `RESET` | POR |
| `PORT1` | GPIO P1 |
| `TIMER0_A0` | Timer — [10-timers.md](../10-timers.md) |
| `USCI_A0` | UART/SPI |
| `USCI_B0` | I²C/SPI — [17-i2c.md](../17-i2c.md) |
| `ADC10` | ADC — [12-adc.md](../12-adc.md) |

Priority via **interrupt enable** bits; no ARM-style NVIC preemption levels.

## Low Power Focus

MSP430 excels at **LPM3/LPM4** — sub-µA with GPIO wake. Measure with LaunchPad **EnergyTrace** if available.

Compare sleep modes to [esp32-s3.md](./esp32-s3.md) deep sleep — different trade-offs (FRAM retention, wake time).

---

## When to Choose MSP430

- Battery + energy harvesting (solar, CR2032 years)
- Simple sensing + RF module (ESP as coprocessor)
- Academic ultra-low-power curriculum

For Rust-first wireless, [esp32-c3.md](./esp32-c3.md) or [nrf52.md](./nrf52.md) offer richer HAL.
