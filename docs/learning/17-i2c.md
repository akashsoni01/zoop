## Theory

**I²C** (Inter-Integrated Circuit, pronounced "I-squared-C" or "I-two-C") is a **two-wire**, **multi-master-capable**, **half-duplex** bus:

| Signal | Role |
|--------|------|
| **SDA** | Serial Data |
| **SCL** | Serial Clock (driven by master) |

Both lines are **open-drain** with **pull-up resistors** (typically 4.7 kΩ on 3.3 V systems, shorter buses can use 2.2 kΩ).

### Addressing

Each slave has a **7-bit address** (10-bit exists but is rare). The master sends:

```
START | ADDR[6:0] + R/W bit | ACK | DATA... | STOP
```

- **R/W = 0:** master writes to slave  
- **R/W = 1:** master reads from slave  

Multiple devices share the bus if addresses differ. Address conflicts require a **multiplexer** (e.g., TCA9548A) or separate buses.

### ACK / NACK

**ACK** (Acknowledge): receiver pulls SDA low during the 9th clock pulse — "byte received OK".  
**NACK** (Not Acknowledge): SDA left high — "error or stop read cycle".

Common NACK causes: wrong address, device not powered, bus stuck, missing pull-ups.

### Clock Stretching

A slow slave may **hold SCL low** after the master releases it — the master must wait. Most ESP32 I²C hardware supports stretching detection; bit-banged implementations often miss this.

### Speed modes

| Mode | Max clock | Notes |
|------|-----------|-------|
| Standard | 100 kHz | Safe default |
| Fast | 400 kHz | Common on sensors |
| Fast Mode Plus | 1 MHz | Check pull-ups and trace length |

## Hardware Overview

### ESP32-S3 I²C

Two controllers (**I2C0**, **I2C1**), configurable pins via **GPIO matrix**. Features:

- Master mode (typical)
- Hardware filter for glitches
- Timeout / SCL stuck recovery on some HAL versions
- Interrupt-driven or polling transfers

Default DevKitC-1 often breaks out I²C on labeled pins — verify schematic in [boards/esp32-s3.md](./boards/esp32-s3.md).

### Common I²C peripherals

| Part | Address | Function |
|------|---------|----------|
| BME280 | 0x76 / 0x77 | Temp/humidity/pressure |
| SSD1306 OLED | 0x3C | Display |
| MPU6050 | 0x68 | IMU |
| PCF8574 | 0x20–0x27 | GPIO expander |

## ASCII Wiring

```
ESP32-S3              BME280 Module
┌──────────┐          ┌──────────┐
│ GPIO8    ├── SDA ──┤ SDA      │
│ GPIO9    ├── SCL ──┤ SCL      │
│ 3V3      ├─────────►│ VIN      │
│ GND      ├─────────►│ GND      │
└──────────┘          └──────────┘
     │    │
     └────┴── 4.7 kΩ pull-ups to 3V3 (often on breakout board)
```

**Star topology vs daisy chain:** Keep bus capacitance low; long cables need stronger pull-ups or lower speed.

## Memory & Register Notes

### ESP32-S3 I²C registers (conceptual)

| Register | Purpose |
|----------|---------|
| `I2C_SCL_LOW` / `HIGH` | Timing counters |
| `I2C_DATA` | TX/RX FIFO |
| `I2C_INT_STATUS` | Complete, NACK, timeout |
| `I2C_CMD` | Sequence START/WRITE/READ/STOP |

Timing derives from **APB clock** — recalculate after sleep/wake — [24-low-power.md](./24-low-power.md).

### Transaction buffer

```rust
// Write register 0xF4 on BME280, then read 3 bytes
let mut buf = [0u8; 3];
// write: [0xF4] then read into buf — HAL combines as write_read
```

## HAL Example — I²C Scanner (esp-hal)

Scans addresses 0x08–0x77 and prints responding devices:

```rust
use esp_hal::{
    gpio::Io,
    i2c::master::I2c,
    peripherals::Peripherals,
};
use core::fmt::Write;
use esp_hal::uart::{Uart, config::Config};

fn main() -> ! {
    let peripherals = Peripherals::take();
    let io = Io::new(peripherals.GPIO, peripherals.IO_MUX);

    // Console UART for output
    let mut uart = Uart::new(peripherals.UART0, Config::default().baudrate(115_200))
        .unwrap()
        .with_tx(io.pins.gpio43);

    // I2C0 on GPIO8/9 — change to match your wiring
    let i2c = I2c::new(
        peripherals.I2C0,
        io.pins.gpio8,  // SDA
        io.pins.gpio9,  // SCL
        100.kHz(),      // Standard mode for bring-up
    )
    .unwrap();

    writeln!(uart, "I2C scanner...\r\n").ok();

    for addr in 0x08u8..=0x77 {
        // Probe: attempt write of 0 bytes (some HALs use write_read with empty)
        let probe_addr = (addr << 1) as u8; // 7-bit to 8-bit write address
        match i2c.write(addr, &[]) {
            Ok(()) => {
                writeln!(uart, "Found device at 0x{:02X}\r\n", addr).ok();
            }
            Err(_) => {
                // NACK — no device at this address (normal)
            }
        }
    }

    writeln!(uart, "Scan complete.\r\n").ok();

    loop {}
}
```

Note: Some devices NACK empty writes but respond to `write_read` — if a known device is missed, try reading a register.

## Portable embedded-hal Pattern

```rust
use embedded_hal::i2c::I2c;

fn read_bme280_chip_id<I2C: I2c>(i2c: &mut I2C) -> Result<u8, I2C::Error> {
    const ADDR: u8 = 0x76;
    let reg = [0xD0]; // CHIP_ID register
    let mut id = [0u8];
    i2c.write_read(ADDR, &reg, &mut id)?;
    Ok(id[0])
    // Expect 0x60 for BME280
}
```

Works on ESP32, STM32 (`stm32f4xx-hal`), RP2040 (`rp2040-hal`) with different init.

```rust
// Bit-bang I2C — teaching only; use hardware peripheral in production
fn i2c_start() { /* SDA high→low while SCL high */ }
fn i2c_stop()  { /* SDA low→high while SCL high */ }
fn i2c_write_byte(b: u8) -> bool {
    // Shift MSB first; sample ACK on 9th clock
    true // true if ACK received
}
```

Hardware I²C frees CPU and handles stretching correctly.

## Step-by-Step

1. Wire SDA, SCL, power; confirm pull-ups present (measure idle high at 3.3 V).
2. Run **scanner** at 100 kHz — note found addresses.
3. Open device datasheet — map registers.
4. **Read chip ID** register — validate communication.
5. Increase to 400 kHz if signal integrity allows.
6. Wrap in driver crate with error types (`embedded-hal` + `thiserror` on host tests).

## Common Mistakes

| Mistake | Symptom | Fix |
|---------|---------|-----|
| No pull-ups | Bus stuck low, no devices | Add 4.7 kΩ to 3.3 V |
| SDA/SCL swapped | No ACK | Swap wires |
| Wrong 7-bit vs 8-bit address | `0xEF` vs `0x77` confusion | Rust HALs use 7-bit |
| Address conflict | Random failures | Scan bus, use mux |
| 5 V device without level shift | ESP32 damage | Level shifter or 3.3 V part |
| Ignoring clock stretching | Lost bytes on EEPROM | Hardware I²C or compliant bit-bang |
| Long wires at 400 kHz | Errors | Lower speed or stronger pull-ups |

## Debugging Tips

- **Logic analyzer** with I²C decode — instant address/data visibility.
- Multimeter: both lines idle **high** when bus free.
- Scanner finds **nothing** → wiring/pull-ups; finds **everything** → SDA stuck low.
- Read **ACK** bit explicitly in bare-metal bring-up.
- Compare against `i2cdetect` on Linux with USB adapter — same wiring.

---

## Performance Tips

- **400 kHz** unless trace length or slaves require 100 kHz.
- Batch register reads — BME280 burst read is faster than three singles.
- **embedded-hal-async** + Embassy for concurrent bus access with mutex — [22-embassy.md](./22-embassy.md).
- Cache repeated writes (display) in RAM; I²C is slow for full framebuffer — prefer SPI for displays — [16-spi.md](./16-spi.md).
